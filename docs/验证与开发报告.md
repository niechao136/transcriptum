构建加速：国内构建需传 `--build-arg PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple`
与 `--build-arg APT_MIRROR=http://mirrors.tuna.tsinghua.edu.cn/debian`，
否则国际源下载速度约 15 kB/s，耗时超过 10 分钟。详见 [Docker 部署指南](Docker部署指南.md)。

容器化过程中发现并修掉的真实问题：
1. **`.env.example` / compose 变量名不一致**：`ALLOWED_DOMAINS` vs 代码里的 `ALLOWED_EGRESS`，
   会导致白名单配置静默失效 → 统一为 `TRANSCRIPTUM_ALLOWED_EGRESS`。
2. **出网白名单有内网后门**：`_domain_allowed` 对所有内网地址无条件放行，
   与"所有端点必须显式加白名单"的安全约束冲突 → 移除后门，白名单成为唯一授权来源。
3. **entrypoint 传 `--days` 但 CLI 不支持**：文档里的 purge 命令无法执行 → 补 `--days` 参数。
4. **compose 服务名与文档不一致 / 缺 split profile worker**：API 多副本拆分无法用
   → 服务改名 `transcriptum`（去掉 container_name 以支持 scale），新增 `transcriptum-worker`。

## 三、开发过程中发现并修掉的真实缺陷

这些不是测试写错，是实现的问题；每条都补了回归测试。

1. **音频路径自我覆盖**（严重）
   `service.create` 把原始上传文件与归一化目标都写成 `{rec_id}.wav`，
   归一化会覆盖原始文件，导致 §10 要求的"保留原始音频可重跑 ASR"失效。
   → 改为 `original/` 与 `audio/` 分离，且归一化后才回填 `audio_path`。

2. **详情接口不含 segments**
   校对台需两次请求且易读到空列表；前端与冒烟脚本都按"含 segments"实现。
   → `service.get` 返回 `segments`、`review_progress`、`has_audio`。

3. **`asr_text` 修改被静默忽略**
   SQLite 触发器本身有效（已单独验证会 `RAISE(ABORT)`），但 API 层把该字段
   直接过滤掉并返回 200，调用方会误以为改成功。
   → 改为显式 422 拒绝。

4. **中文标题无法导出**
   `Content-Disposition` 直接塞中文会触发 latin-1 编码错误。
   → 改为 RFC 5987（ASCII 回退名 + `filename*=UTF-8''`）。

5. **评估接口响应不完整**
   创建/更新字段返回裸行或缺 `submittable`/`blockers`，前端无法判断能否提交。
   → 统一返回完整评估载荷（含 framework、values、submittable、blockers）。

6. **受保护 token 识别漏掉混合大小写缩写**
   `HbA1c`、`CT` 这类未被 `[A-Z]{2,}` 覆盖。
   → 修正正则并加测试。

7. **改动幅度判定误伤正常纠错**
   原先按"所有 edit 长度之和 / 原文长度"，中文同音字替换（等长）也会超阈值。
   → 改为"最终文本相对原文的净长度变化比例"，语义正确。

8. **审计接口缺失**
   §10 要求可查"谁何时改了哪句"，原先只有写没有读。
   → 新增 `GET /api/recordings/{id}/audit`。

## 四、设计文档要求的落地对照

### §7.5 时间重叠对齐（文档称"唯一真正困难的地方"）

三步实现，每条失败情形都有对应行为而不是猜：

| 失败情形 | 处理 |
| --- | --- |
| 分离把重叠语音整段给一个标签 | 按重叠时长 argmax，天然保证"一句一人" |
| 前两名重叠接近（差 < `ambiguous_margin`） | 标 `needs_review_speaker`，强制人工确认 |
| 字幕与说话人时间不完全对齐 | 容差内正常归属；完全无重叠 → 最近块 + 待确认 |
| 覆盖比例过低（< `min_overlap_ratio`） | 最近块 + 待确认 |
| 说话人切换发生在句中 | `midpoint_split` 按实际分界点切分，文本优先吸附标点；切不开则标待确认 |

### §4.3 保守校对"不许编"

- 受保护 token（剂量、数值、缩写）命中修改 → 丢弃并告警 `protected_token_modified`；
- 模型给出与逐处替换不一致的 `corrected_text` → 以逐处替换为准，告警 `model_rewrote`；
- 净长度变化 > 30% → 不采纳，标待复核；
- `from` 在原文中找不到 → 丢弃，绝不凭空插入；
- 模型/网络失败 → 保留原文 + `requires_review`，不阻塞流水线。

### §6 引用强制

每个字段必须有 `citations`（有效 seq），否则 `missing_citation`；
`can_submit` 在必填缺失、无引用、类型不符时返回具体 blockers；
提交接口在不可提交时返回 422 并带原因列表。

## 五、尚未验证 / 需要目标机确认

**这一节请务必在切生产前处理。**

1. **MOSS 真实输出格式**
   解析器按官方 README 的 `[0.00][S01]文本` 实现，并已对文档样例与
   `[mm:ss.xx]` 两种格式自测通过。但真实模型输出可能有换行、标点、
   空段的细微差异。**目标机上先跑：**

   ```bash
   python scripts/probe_moss.py --base http://127.0.0.1:9000
   ```

   它会打印原始返回并用本项目的解析器试解析；失败会直接指出差异所在。

2. **性能（RTF）与显存**
   文档里 2060S 8GB + fp16 的估算没有实测支撑。
   需要实测：长音频（≥60 min）是否 OOM、是否需要分段、真实 RTF。

3. **vLLM/SGLang 的作业接口路径**
   `custom_http.submit_path / poll_path / fetch_path` 是按通用三段式写的占位，
   **必须按实际服务改**。

4. **frontend 未做浏览器人工走查**
   类型检查与构建通过，但没有在真实浏览器里点过一遍。
   建议 `npm run dev` 后手动确认：跳播是否精确到句、键盘流程是否顺手、
   diff 高亮位置是否对得上。这是纯体验验证，代码层面的错误已被 tsc 拦住。

5. **热词表与术语库未接真实数据**
   `glossary` 表与 `_glossary_pairs` 已就位，但试点前应导入科室术语，
   否则 MOSS 的专有名词识别率会明显偏低。
