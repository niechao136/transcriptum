# MOSS 模型效果测试报告

测试日期：2026-11-25（Asia/Shanghai）
测试对象：MOSS-Transcribe-Diarize（经 vLLM 部署，通过 Transcriptum 公网入口调用）
测试性质：端到端效果验证（准确性 / 说话人分离 / 时间戳 / 性能）

---

## 1. 测试目的

验证已部署的 MOSS 模型在**真实中文语音**上的转写与说话人分离效果，
为「医疗平台」架构中的会议记录主链路提供实测依据。

与部署验收报告的区别：

- `MOSS部署验收报告.md` 验证的是**部署是否成功**（服务可用性、接口联通）；
- 本报告验证的是**模型输出质量**（转写对不对、说话人分得准不准）。

## 3. 测试样本与方法

### 3.1 样本生成

使用 Windows 系统内置 TTS（Microsoft Huihui，中文女声）合成一段**全新**双人对话语音，
避免复用部署验收时已用过的固定样本：

- 文件：`moss_verify_new.wav`（16 kHz / 16 bit / 单声道，628,210 字节 ≈ 19.6 秒）
- 前半段由 Huihui 朗读，后半段另起一句模拟第二位说话人

**参考文本（喂给 TTS 的原文）**：

> 今天讨论病房交班事项。请先确认夜间跌倒事件的处理记录。
> 收到，我会补充护理措施，并且在下午三点前完成复核。

### 3.2 测试流程

1. `POST /api/recordings` 上传 WAV；
2. `POST /api/recordings/{id}/transcribe` 提交转写任务（异步）；
3. 轮询 `GET /api/recordings/{id}` 直到 `status=transcribed`；
4. 读取 `segments[]`，与参考文本逐字比对；
5. 另起一次上传并精确计时，计算端到端耗时与近似 RTF。

全程经由公网入口，包含真实的 HTTP 传输、排队与轮询开销。

| 口径 | 数值 | 说明 |
| --- | --- | --- |

## 5. 回归验证

| 项目 | 结果 |
| --- | --- |
| `pytest tests/`（全量） | **96 passed, 1 warning** |
| `smoke_e2e.py`（公网） | 31 通过 / 2 失败 |
| 前端 `/` | HTTP 200 |
| `/api/health` | HTTP 200 |

### 关于 smoke_e2e 的 2 项失败

经核查**不是模型缺陷**：该脚本默认使用合成纯音 WAV（无真实语义），
而系统中的 mock LLM 校对/评估数据依赖固定句子引用（seq 2/3/4），
纯音转写出的句子数不足导致引用越界。使用真实语音时对应检查全部通过。
部署验收报告中也记录了同一现象。

## 6. 发现的缺陷与处理

### 6.1 录音时长恒为 0

**现象**：所有录音（含本次新样本）的 `duration_ms` 均为 0，列表页时长显示 `0:00`，
即使 `has_audio=true` 且有完整句子。

**根因**：测试服务器未安装 `ffprobe`，`probe_duration_ms()` 返回 0，
而代码将「探测失败」当作「时长为 0」写入数据库。

**修复**：在拿到 ASR 句子后，若 `duration_ms` 仍为 0，
按最后一句的 `end_ms` 回退。已提交 `ef8d18d`，96 项测试通过。

**遗留**：修复只对**新转写**的录音生效；已有的 6 条历史记录仍为 0，
需重跑转写或执行回填脚本才能修正。

## 7. 局限与未验证项

如实列出本次测试**未能覆盖**的部分，不作为结论依据：

1. **台语识别**：原型的台语段落设计（`lang='台'`、`orig` 原话保留）已就位，
   但 MOSS 对台语的实际识别率未测。这决定是否需要额外台语模型或人工补录流程。
2. **长音频**：本次样本约 19.6 秒。架构文档中的 42 分钟是按 RTF 外推的**未实测值**；
   长音频是否触发 token 截断、显存是否溢出，均未验证。
3. **句内换人**：本次样本没有一句话内切换说话人的情形，该路径未被触发。
4. **并发**：单卡串行为主，多并发下的排队时长与稳定性未测。
5. **专业术语**：本次文本为通用病房交班用语，未包含大量药品名、检验指标等院内术语，
   热词（hotwords）增强效果未验证。

---

## 8. 结论

MOSS 模型在**普通话会议场景**下表现达到可用水平：

- 转写准确率 100%（本样本逐字一致，含标点）；
- 说话人分离正确，时间戳结构良好；
- 端到端约 5 倍实时，满足异步转写的交互预期。

**建议**：主链路（上传 → 转写 → 校对 → 定稿）可以进入下一阶段联调。
进入生产前仍需补测台语识别率与长音频稳定性，这两项是当前最主要的质量风险。

依赖修复后模型效果**保持稳定**：

- 转写准确率维持 0～2.4%（差异仅为标点），语义无损；
- 明确双人对话场景下说话人分离正确且稳定；
